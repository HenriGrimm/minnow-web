# Content voice

Copied from the Minnow spec §1.2 (from the app's `PRODUCT.md`). These rules are **binding** for
everything written on this site.

## Voice

- Plain and unhurried. State what a thing does and stop.
- **No exclamation marks.** No hype ("autonomous AGI"). No growth-marketing cadence.
- Write like project documentation, not a landing page: short declaratives, real nouns, second person.
- "Free and open source" is said **once**, plainly. It is the premise, not a badge.
- Privacy is stated plainly, never fear-marketed.
- Naming competitors is allowed — but only the seven sanctioned rows in spec §1.4, never disparaging,
  and always paired with what the integration buys.
- **Claims discipline:** everything describes what ships today. Nothing in the future tense.

## Banned content

Never mention: **Research**, **Experts**, **Benchmarking**, **Compare**, **Super Plan** (all
release-gated), an **Email** app, a **Studio** app, or agent-CLI providers
(claude/codex/cursor). None exist. `app-research.png` must never be used.

## Do not copy README typos

"intergrated", "availible", "combinded", and the stray fragment `| a fully intergrated issue` on
README line 29. Rewrite those rows cleanly.

## When in doubt

Write like project documentation.
